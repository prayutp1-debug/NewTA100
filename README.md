# TA รถโม่ — Dashboard คะแนนวันทำงานและรางวัล

Dashboard สรุปคะแนนวันทำงานของรถโม่ (truck_no) การคำนวณเงินรางวัล/การันตี
และการตัดเงินรางวัลของ จบส. (driver_no)

## เข้าสู่ระบบ

หน้าเว็บมีหน้า login กั้นไว้ ใช้ **ฐานข้อมูลผู้ใช้ชุดเดียวกับเว็บแอปอื่น** (กูเกิลชีต User
ที่เก็บคอลัมน์ Name / User / Password / Status) และเปลี่ยนรหัสผ่านผ่าน Apps Script
ตัวเดียวกัน — เปลี่ยนที่นี่แล้วใช้ได้กับทุกเว็บแอปที่ใช้รายชื่อชุดนี้

- ช่องรหัสผ่านทุกช่องมีปุ่มรูปดวงตาสำหรับเปิด/ปิดการมองเห็น
- ใต้ช่องรหัสผ่านมีข้อความแจ้งแบบทันทีขณะพิมพ์ — บอกจำนวนตัวอักษรที่พิมพ์ไปแล้ว
  เตือนเมื่อเปิด Caps Lock อยู่ และบอกเมื่อรหัสผ่านไม่ถูกต้อง
- ในกล่องเปลี่ยนรหัสผ่าน ข้อความจะตรวจให้ทันทีว่ารหัสใหม่สั้นเกินไป ซ้ำกับรหัสเดิม
  หรือยืนยันยังไม่ตรงกัน และปุ่มบันทึกจะกดไม่ได้จนกว่าจะถูกต้องครบทุกช่อง
- ติ๊ก “จำการเข้าสู่ระบบ” แล้วครั้งต่อไปจะเข้าให้อัตโนมัติ
- ปุ่ม **เปลี่ยนรหัสผ่าน** อยู่ทั้งในหน้า login และมุมขวาบนหลังเข้าระบบ
- ปุ่ม **ออกจากระบบ** อยู่มุมขวาบน
- ปุ่ม **ลืมรหัสผ่าน?** ในหน้า login — เปิด popup 3 ขั้นแบบเดียวกับเว็บแอปอื่น

### ขั้นตอนลืมรหัสผ่าน

1. **ค้นอีเมล** — เรียก `action=lookupUser&user=<ชื่อผู้ใช้>` เพื่ออ่านอีเมลที่บันทึกไว้
   (ยังไม่เปลี่ยนรหัสและยังไม่ส่งอีเมล)
2. **ยืนยัน** — แสดงชื่อผู้ใช้และรายการอีเมลปลายทางให้ตรวจก่อน พร้อมคำเตือนว่ารหัสเดิมจะใช้ไม่ได้
3. **ตั้งรหัสใหม่และส่ง** — เรียก `action=forgotPassword&user=<ชื่อผู้ใช้>` เขียนรหัสใหม่ลงชีต
   แล้วส่งอีเมล จากนั้นล้างรหัสที่จำไว้ในเครื่องให้อัตโนมัติ

ถ้า Apps Script ตอบ error เรื่องสิทธิ์ส่งอีเมล popup จะแสดงวิธีแก้ให้ทันที
(เปิด Apps Script → รันฟังก์ชัน `authorizeMail` → Allow → Deploy เวอร์ชันใหม่)

### ถ้าเข้าสู่ระบบไม่ได้

หน้า login ตรวจรหัสผ่านกับ **Apps Script** เป็นหลัก ถ้าเรียกไม่ได้หรือไม่ยืนยันจึงเทียบกับรายชื่อในกูเกิลชีต
เมื่อเข้าไม่ได้จะมีกล่องสีแดง**เหนือปุ่มเข้าสู่ระบบ** บอกว่าใครเป็นผู้ปฏิเสธ

| ข้อความ | ความหมาย |
|---|---|
| ผลตรวจจาก Apps Script: ไม่ตรงกับที่บันทึกไว้ | Apps Script ปฏิเสธโดยตรง — รหัสผ่านในฐานข้อมูลผู้ใช้ไม่ตรงกับที่พิมพ์ |
| เรียก Apps Script ไม่ได้ จึงเทียบกับรายชื่อในกูเกิลชีตแทน … | เชื่อมต่อ Apps Script ไม่ได้ และรหัสผ่านในชีตไม่ตรงกับที่พิมพ์ |
| Apps Script ไม่ยืนยัน และไม่พบคู่ชื่อผู้ใช้/รหัสผ่านนี้ในกูเกิลชีต | Apps Script ตอบแบบไม่ชัดเจน และในชีตไม่มีคู่นี้ |

สิ่งที่ควรเช็คก่อน: รหัสผ่านในชีต User ของผู้ใช้นั้น (ตัวพิมพ์เล็กใหญ่ ช่องว่างหน้าหลัง)
และเคยกด “ลืมรหัสผ่าน?” หรือ “เปลี่ยนรหัสผ่าน” ไว้หรือไม่ เพราะทั้งสองอย่างเปลี่ยนรหัสผ่านในชีตทันที
(รหัสเดิมใช้ไม่ได้อีก และมีผลกับทุกเว็บแอปที่ใช้ฐานข้อมูลผู้ใช้ชุดเดียวกัน)

### ปุ่มสำหรับผู้ดูแลระบบ

ปุ่ม **โหลดข้อมูลใหม่**, **ใช้ไฟล์ Excel อื่น** และ **บันทึกไฟล์ข้อมูล** ที่แถบด้านบน
(รวมถึงปุ่ม “เลือกไฟล์ Excel จากเครื่อง” บนหน้าจอแจ้งเปิดฐานข้อมูลไม่ได้)
แสดงเฉพาะผู้ใช้ที่อยู่ในรายชื่อ `ADMIN_USERS` ใน `index.html` — ตอนนี้คือ **`sirilukt`**
ผู้ใช้อื่นจะไม่เห็นปุ่มเหล่านี้ (ปุ่ม เปลี่ยนรหัสผ่าน และ ออกจากระบบ ยังแสดงตามปกติ)

```js
var ADMIN_USERS  = ['sirilukt'];   // เพิ่มได้ เช่น ['sirilukt','somchai'] เทียบกับช่อง User ในชีต ไม่สนตัวพิมพ์เล็กใหญ่
```

> สิทธิ์ผู้ดูแลแยกจากสิทธิ์การมองเห็นข้อมูล — ถ้าต้องการให้ผู้ดูแลเห็นข้อมูลทุกผู้รับเหมา
> ช่อง Status ของผู้ใช้นั้นในชีต User ต้องมีคำว่า SCG ด้วย
>
> การซ่อนปุ่มเป็นการจำกัดที่หน้าจอ ไม่ใช่การป้องกันไฟล์ข้อมูลใน repo

### สิทธิ์การมองเห็น

ใช้เกณฑ์เดียวกับเว็บ SDA โดยดูจากคอลัมน์ `Status` ในชีต User

| Status | เห็นอะไร |
|---|---|
| มีคำว่า **SCG** | ทุกผู้รับเหมา ทุกคัน |
| อื่น ๆ (ผู้รับเหมา) | เฉพาะรถและคนขับของตนเอง |

การจับคู่ใช้ **รหัสผู้ใช้เทียบกับ `vendor_id`** ก่อน ถ้าไม่ตรงจึงเทียบ **ชื่อผู้ใช้กับชื่อผู้รับเหมา**
(ตัดช่องว่างและเครื่องหมายออกก่อนเทียบ) การกรองทำที่ชั้นข้อมูล จึงมีผลกับทุกอย่าง —
KPI, กราฟ, ทุกตาราง, ตัวเลือกในตัวกรอง และไฟล์ Excel ที่บันทึกออกไป

แถบหัวจะขึ้นป้ายบอกสิทธิ์ที่ได้รับเสมอ ถ้าเข้าระบบได้แต่ไม่พบรถของผู้รับเหมานั้น
จะขึ้นข้อความบอกชื่อและรหัสที่ใช้จับคู่ เพื่อให้ตรวจสอบกับชีต User ได้

ตั้งค่าได้ที่ 4 ตัวแปรต้นบล็อก `<script>` หลักใน `index.html`

```js
var USER_SHEET   = '...';         // กูเกิลชีตเก็บ user/password
var USER_CSV_URL = '';            // (ถ้ามี) ลิงก์ CSV แบบเผยแพร่
var LOCAL_CSV    = 'users.csv';   // สำรอง: วางไฟล์ CSV ไว้ข้าง index.html
var API_URL      = '...';         // Apps Script สำหรับ login + เปลี่ยนรหัสผ่าน
```

ระบบจะไล่โหลดรายชื่อผู้ใช้หลายวิธีจนกว่าจะสำเร็จ (CSV เผยแพร่ → gviz → JSONP → ไฟล์
`users.csv` ข้าง index.html) ถ้าไม่สำเร็จเลยจะขึ้นรายละเอียดให้ดูในหน้า login

## ไฟล์ในโปรเจกต์

ไฟล์ที่ต้องอยู่ใน repo (วางที่ชั้นบนสุดได้เลย)

```
index.html               หน้า Dashboard ทั้งหมด (~0.6 MB)
TA100-base.json.gz       ข้อมูลหลัก + รายชื่อเดือนที่จะแสดง (~0.07 MB)
TA100-2026-09.json.gz    ข้อมูลเดือน Sep (~1.0 MB)
TA100-2026-10.json.gz    ข้อมูลเดือน Oct (~0.2 MB)
TA100-2026-11.json.gz    ข้อมูลเดือน Nov (~0.002 MB)
```

ข้อมูลถูกแยกเป็น**รายเดือน ไฟล์ละไม่ถึง 1.2 MB** จึงอัปผ่านหน้าเว็บ GitHub ได้สบาย
(หน้าเว็บจำกัดไฟล์ละ 25 MB) เดือนหน้ามีไฟล์ใหม่เพิ่มอีกหนึ่งไฟล์ ไม่มีไฟล์ไหนโตขึ้น
และ**เดือนเก่าไม่ต้องอัปซ้ำ** เพราะเนื้อหาไม่เปลี่ยน

**ไม่ต้องอัป `TA100.xlsx` ขึ้น repo** — ผู้ใช้คนอื่นเปิดหน้าเว็บก็เห็นข้อมูลครบทุกแท็บ
ทุก comment และบันทึก Excel ได้เหมือนเดิม ไฟล์ Excel ใช้เฉพาะตอนสร้างไฟล์ข้อมูลใหม่
ซึ่งทำบนเครื่องของคุณเอง (ถ้าอัปขึ้น repo ด้วยก็ได้ ระบบจะใช้เป็นตัวสำรอง)

หน้าเว็บมองหาไฟล์ในโฟลเดอร์ `data/` ก่อน แล้วค่อยมองที่ชั้นบนสุดของ repo ถ้ามีไฟล์รุ่นเก่า
`TA100.json.gz` / `TA100.json` ค้างอยู่ก็ลบทิ้งได้ (ระบบใช้ชุดรายเดือนก่อนเสมอ)

ถ้าลืมอัปไฟล์ของเดือนใดเดือนหนึ่ง หน้าเว็บจะยังเปิดได้ แสดงเดือนที่เหลือ
และเขียนเตือนที่มุมขวาบนว่า “ไม่พบไฟล์ข้อมูลเดือน …”

> **ระวัง** ถ้ากดบันทึกโดยยังไม่ได้เลือก Excel (หรือกด “โหลดข้อมูลใหม่”) จะได้ไฟล์ชุดเดิมที่โหลดมาจาก repo
> ไม่มีเดือนใหม่ กล่องข้อความหลังบันทึกจะขึ้นเตือน “⚠ ข้อมูลชุดนี้โหลดมาจาก repo”
>
> **เอาเดือนเก่าออกจากหน้าเว็บ** — หน้าเว็บแสดงเฉพาะเดือนที่อยู่ในรายชื่อของ `TA100-base.json.gz`
> ถ้าไม่ต้องการแสดงเดือนไหน ให้สร้าง base ใหม่ที่ไม่มีเดือนนั้น แล้วลบไฟล์ `TA100-<เดือน>.json.gz` ของเดือนนั้นออกจาก repo
> (ไฟล์เดือนอื่นไม่ต้องแตะ)
>
> **อัปคู่กันเสมอ** — เวลาเปลี่ยนไฟล์ข้อมูล ให้อัป `index.html` เวอร์ชันล่าสุดไปด้วย
> แล้วเปิดหน้าเว็บด้วย `?v=<เลขเวอร์ชัน>` เพื่อเลี่ยง cache ของเบราว์เซอร์และ GitHub Pages

## สร้างไฟล์ข้อมูลใหม่ (ทำทุกเดือน)

1. เปิด Dashboard แล้วกดปุ่ม **“ใช้ไฟล์ Excel อื่น”** มุมขวาบน เลือก `TA100.xlsx` จากเครื่องตัวเอง
2. รอจนขึ้น**แถบสีฟ้า “อ่านไฟล์ TA100.xlsx สำเร็จ”** ซึ่งจะบอกเดือนที่พบใน Excel ว่ามีอะไรบ้าง
   (ถ้าไม่เห็นเดือนใหม่ในแถบนี้ แปลว่า Excel ไม่มีข้อมูลเดือนนั้น) จากนั้นกดปุ่ม
   **“บันทึกไฟล์ข้อมูล”** จะได้ไฟล์ **`TA100-data.zip`**
   — กล่องข้อความหลังบันทึกจะบอกชื่อไฟล์และเดือนทั้งหมดที่อยู่ในชุดนี้
3. แตก zip แล้วอัปไฟล์ข้างในขึ้น repo ทับของเดิม — ต้องอัป `TA100-base` กับไฟล์ของเดือนใหม่
   เป็นอย่างน้อย (เดือนเก่าที่เนื้อหาไม่เปลี่ยนไม่ต้องอัปซ้ำ)

หน้าเว็บอ่าน **เดือน/ปีจากคอลัมน์ `work_date` ในชีต Punch** เอง และดึงจำนวนวันทำงาน
จากชีต `วันทำงาน` ให้อัตโนมัติ — ไม่ต้องแก้อะไรในโค้ด

ถ้าเบราว์เซอร์ไม่รองรับการบีบอัด จะได้ไฟล์ `.json` ธรรมดาแทน ซึ่งใหญ่ขึ้น (เดือนละราว 12 MB)
แต่ยังต่ำกว่าขีดจำกัด 25 MB และใช้งานได้เหมือนกัน

ชีตที่ต้องมีในไฟล์ Excel: `Punch`, `จดทะเบียน`, `การันตี`, `เวลาทำงาน`,
`วันทำงาน`, `คะแนน-Punch`

ชื่อกลุ่มในชีต `คะแนน-Punch` เขียนได้หลายแบบ ระบบจะเทียบแบบไม่สนตัวพิมพ์และช่องว่าง
เช่น `device_no`, `device_in / Out` ถือเป็นกลุ่มเดียวกัน และ `punch_Out_adj_remark`
ก็นับเป็น `punch_out_adj_remark` — ถ้าขาดชีตไหน หน้าเว็บจะบอกชื่อชีตที่หายไป

## ขึ้น GitHub Pages

อัปไฟล์ขึ้น repo แล้วเข้า **Settings → Pages → Source: Deploy from a branch →
main / (root) → Save** รอ 1–2 นาที เว็บจะอยู่ที่
`https://<user>.github.io/<repo>/`

ถ้าแก้ไฟล์แล้วหน้าเว็บยังเป็นของเก่า ให้กด **Ctrl + Shift + R** (hard refresh)
หรือเปิดลิงก์ต่อท้ายด้วย `?v=2` เพราะ GitHub Pages มี CDN cache ประมาณ 10 นาที

### ทดสอบบนเครื่องก่อน

ดับเบิลคลิก `index.html` จะใช้ไม่ได้ เพราะเบราว์เซอร์บล็อกการอ่านไฟล์ข้างเคียง
ผ่าน `file://` ให้รันเซิร์ฟเวอร์เล็ก ๆ แทน

```bash
python -m http.server 8000
# เปิด http://localhost:8000
```

หรือกดปุ่ม **“เลือกไฟล์ Excel จากเครื่อง”** ในกล่องแจ้งเตือน ก็ใช้งานได้เหมือนกัน

## ลดขนาดไฟล์ Excel โดยไม่ทำให้เดือนเก่าหาย

ลบแถวของเดือนเก่าออกจากชีต `Punch` ใน Excel ได้เลย (เช่น ลบ Aug 2026 ไฟล์จะเล็กลงราวครึ่งหนึ่ง)
เดือนเก่ายังอยู่ในไฟล์ข้อมูลรายเดือนที่อัปไว้แล้ว และระบบจะต่อให้เองตอนสร้างไฟล์ใหม่

1. เปิด Dashboard (โหลดจากไฟล์ข้อมูลใน repo — เห็นเดือนครบอยู่แล้ว)
2. กด **“ใช้ไฟล์ Excel อื่น”** เลือก `TA100.xlsx` ที่ลบเดือนเก่าออกแล้ว
3. ระบบคำนวณเดือนที่มีใน Excel แล้ว**ต่อเดือนเก่าจากไฟล์ข้อมูลเดิมเข้าให้อัตโนมัติ**
   (แถบมุมขวาบนเขียนว่า “ต่อเดือนเก่าจากไฟล์ข้อมูลเดิม: Aug 2026”)
4. กด **“บันทึกไฟล์ข้อมูล”** แล้วอัปไฟล์ในซิปทับของเดิม

กติกา: เดือนที่อยู่ใน Excel ใช้ค่าที่คำนวณใหม่เสมอ ส่วนเดือนที่ไม่มีใน Excel
ดึงจากไฟล์ข้อมูลเดิมตามที่เคยคำนวณไว้ทุกตัวเลข (ทดสอบแล้วตรงกัน 100%)

> ชีตอื่น (`จดทะเบียน`, `การันตี`, `วันทำงาน`, `เวลาทำงาน`, `คะแนน-Punch`) ต้องอัปเดตให้ครบเสมอ
> เดือนเก่าที่ต่อมาจะใช้ค่าที่คำนวณไว้แล้ว ไม่คำนวณใหม่จากชีตเหล่านี้

## เรื่องความเร็ว

ไฟล์ Excel ~10 MB มี 53,000 กว่าแถว (ชีต Punch คลายซิปแล้วเป็น XML ขนาด 64 MB)
เปิดครั้งแรกใช้เวลาประมาณ 5–10 วินาทีหลังดาวน์โหลดเสร็จ มีแถบแสดงความคืบหน้าบอกทุกขั้น
หลังจากนั้นผลคำนวณจะถูกจำไว้ใน IndexedDB ของเบราว์เซอร์ เปิดครั้งต่อไปขึ้นภายใน 1 วินาที

ถ้าอยากให้เร็วขึ้นอีก ลดขนาดไฟล์ Excel ได้โดยลบชีตที่ไม่ได้ใช้ ลบรูปภาพในไฟล์
และเก็บเฉพาะคอลัมน์ที่จำเป็นในชีต Punch

หน้าเว็บเช็ค ETag ของไฟล์ Excel ทุกครั้งที่เปิด ถ้าไฟล์ใน GitHub เปลี่ยน
จะคำนวณใหม่ให้เองโดยอัตโนมัติ ถ้าอยากบังคับคำนวณใหม่กดปุ่ม **“โหลดข้อมูลใหม่”**

การคำนวณทำใน Web Worker เพื่อไม่ให้หน้าเว็บค้าง ถ้าเบราว์เซอร์ไม่รองรับ
จะสลับไปคำนวณบนเธรดหลักให้อัตโนมัติ

> การ commit ไฟล์ 10 MB ทุกเดือนจะทำให้ repo โตเดือนละ ~10 MB
> ถ้าสะสมนานจนใหญ่เกินไป ค่อยพิจารณาใช้ Git LFS หรือเก็บไฟล์ย้อนหลังไว้ที่อื่น

## แท็บในหน้าเว็บ

| แท็บ | เนื้อหา |
|---|---|
| สรุปโครงการ | สรุปรางวัลและรายการหักของทั้งโครงการ เลือกสรุปตาม กิจการ / ภาค / แผนกผลิต / โรงงาน / ผู้รับเหมา พร้อมดาวน์โหลด Excel รูปแบบเอกสารสรุปรายผู้รับเหมา · คอลัมน์ **หักเงิน จบส.** แยกต่างหาก และจะถูกลบออกจากรางวัลสุทธิเฉพาะเมื่อ (เงินรางวัล + การันตี) ของกลุ่มนั้นเป็นบวกจริง มิฉะนั้นจะแสดงยอดไว้เฉย ๆ พร้อมหมายเหตุ |

> การตัดสินว่า “มีเงินรางวัลให้หักหรือไม่” ดูแยกตามกลุ่มที่เลือก — กรณีสรุปรายผู้รับเหมา
> จะแยกตามกิจการอยู่แล้ว ผู้รับเหมารายเดียวที่อยู่หลายกิจการจึงคิดแยกกัน
> ไม่เอารางวัลของกิจการหนึ่งไปกลบค่าปรับของอีกกิจการหนึ่ง
| สรุปโครงการ-รายโรงงาน | เหมือนแท็บสรุปโครงการ แต่แยกรายโรงงาน เพิ่มคอลัมน์ รหัสโรงงาน, โรงงาน และ Cost Center-VC (จากชีต `จดทะเบียน`) |
| ภาพรวม | KPI, การกระจายกลุ่ม TA, **ตารางและกราฟเปรียบเทียบรางวัลรายเดือน** (Incentive / การันตี / รายการหัก / หักเงิน จบส. / คงเหลือสุทธิ พร้อมตัวเลขกำกับบนกราฟ), กลุ่ม TA แยกรายกิจการ, เงินรางวัลรายผู้รับเหมา, สรุปตามกิจการ (คอลัมน์ชุดเดียวกับแท็บสรุปโครงการ ยกเว้น Vendor และบริษัทคู่ธุรกิจ), 15 คันที่ %TA ต่ำสุด |
| คะแนนรายวัน | ตาราง รถ × วันที่ 1–31 แต่ละช่องแสดง **คิว/เที่ยว** สีพื้นคือคะแนนที่ได้ |
| คะแนนวันทำงาน | คอลัมน์เหมือนแท็บคะแนนรายวันทุกช่อง แต่ละช่องแสดง **คะแนนที่ได้ของวันนั้น** พร้อม comment สาเหตุครบถ้วน |
| คำนวณรางวัล | คะแนนรวม, คิว, รายได้, %TA, กลุ่ม TA, เงินรางวัล, การันตี, หักไม่โยก/ย้ายโรงงาน, รางวัลสุทธิ |
| หักเงิน จบส. | ตาราง คนขับ × วันที่ พร้อมยอดรวมที่ถูกหัก — วางเมาส์ที่ช่องที่มีสามเหลี่ยมเพื่อดูสาเหตุ |
| รายละเอียด Punch | รายรายการ พร้อมชื่อโรงงาน, punch_in_time / punch_out_time และยอดหักแยกตามสาเหตุ |
| เกณฑ์คะแนน | ตารางเกณฑ์ทั้งหมดที่ระบบใช้ |

ทุกแท็บมีตัวกรองเดือน — แท็บ **ภาพรวม** เลือกเป็นช่วง **เดือนเริ่มต้น – เดือนสิ้นสุด** ได้ ส่วนแท็บอื่นดูได้ **ครั้งละ 1 เดือน** (ช่อง “เดือน”, เริ่มที่เดือนล่าสุด) และมีตัวกรองลดหลั่น
กิจการ → ภาค → แผนก → โรงงาน → ผู้รับเหมา พร้อมกรองกลุ่ม TA,
ค้นหาเบอร์รถ/คนขับ และปุ่ม **บันทึก Excel**

ไฟล์ที่บันทึกออกมาเป็น `.xlsx` จริง มีสีเหมือนบนหน้าเว็บ (สีคะแนน สีกลุ่ม TA
สีของยอดที่ถูกหัก) ตีเส้นตารางทุกช่องตามจำนวนข้อมูลที่มี ตั้งความกว้างคอลัมน์
และเปิด AutoFilter ที่หัวตารางให้แล้ว ช่อง `truck_no` และ `driver_no`
บันทึกเป็นข้อความเสมอ เลข 0 นำหน้าจึงไม่หาย (เช่น `0018` ไม่กลายเป็น `18`)

ช่องที่มีหมายเหตุบนหน้าเว็บจะกลายเป็น **Comment ของ Excel** วางเมาส์ในไฟล์
แล้วขึ้นข้อความเดียวกับที่เห็นบน dashboard — ช่องคะแนนที่ถูกหัก, ช่องยอดหักเงิน จบส.
และช่องอัตราเงินรางวัลของรถที่ถูกตัดสิทธิ์

Comment ใช้ตัวอักษร 8pt บีบข้อความให้อยู่ใน 4 บรรทัด (หัวเรื่อง 1 + สาเหตุไม่เกิน 3)
และ**ปรับขนาดกรอบให้พอดีกับข้อความของแต่ละช่อง** — ช่องที่ข้อความสั้นกรอบก็เล็ก
ช่องที่ข้อความยาวกรอบก็กว้างขึ้น จึงอ่านได้ครบโดยไม่มีกรอบใหญ่เกินจนบังข้อมูล

> แท็บคะแนนรายวันมี comment ราว 14,000 ช่อง ใช้เวลาสร้างสักครู่
> (มีแถบความคืบหน้าแสดงระหว่างสร้าง)

## การเลือกเดือน

หน้าเว็บอ่านเดือนจากคอลัมน์ `work_date` ในชีต Punch ถ้าไฟล์มีหลายเดือน
ช่องเลือกเดือนจะมีให้เลือกครบทุกเดือน

| แท็บ | วิธีเลือกเดือน |
|---|---|
| **ภาพรวม** | เลือกเป็นช่วงได้ ด้วย “เดือนเริ่มต้น” และ “เดือนสิ้นสุด” (เริ่มต้นที่ทุกเดือน) |
| แท็บอื่นทั้งหมด | ดูได้ **ครั้งละ 1 เดือน** ด้วยช่อง “เดือน” (เริ่มต้นที่เดือนล่าสุด) |

เมื่อเลือกช่วงมากกว่า 1 เดือน (เฉพาะแท็บภาพรวม) ระบบจะ

- รวมคะแนนและคิวของทุกเดือนในช่วง แล้วคิด %TA จาก **วันทำงานรวม** ของช่วงนั้น
- รวมฐานการันตีของทุกเดือนในช่วง แล้วคูณ %การันตีตามกลุ่ม TA ที่ได้

การดูทีละเดือนในแท็บอื่นทำให้เงื่อนไข “ผู้รับเหมาที่ไม่มีรางวัลและการันตีในเดือนนั้น
ไม่ต้องนำค่าปรับ จบส. มาหัก” คิดตามรายเดือนจริง ไม่ปนกับเดือนอื่น

ชื่อไฟล์ Excel ที่บันทึกจะมีเดือนที่เลือกต่อท้าย เช่น `TA_สรุปราย-ผู้รับเหมา_2026-09.xlsx`

ถ้าตัวกรองกิจการ/ภาค/แผนก/โรงงาน/ผู้รับเหมาที่เลือกไว้ไม่มีข้อมูลในเดือนที่เปลี่ยนไป
ระบบจะล้างตัวกรองนั้นให้เอง

> วิธีดูข้อมูลย้อนหลังหลายเดือน: เอาแถว Punch ของเดือนก่อน ๆ ต่อท้ายในชีตเดียวกัน
> และเพิ่มแถวของเดือนนั้นในชีต `วันทำงาน` / `การันตี` / `จดทะเบียน`
> (ชีตเหล่านี้มีคอลัมน์ ปี/เดือน อยู่แล้ว ระบบจะจับคู่ให้เอง)

## วิธีคิดคะแนน

คะแนนตั้งต้น **1 คะแนน/วัน/คัน** แล้วหักตามเหตุการณ์ หักได้ไม่เกิน 1 และได้ไม่เกิน 1

| หักจาก | เกณฑ์ |
|---|---|
| `punch_in_status` | มาสาย (T) = −0.25 |
| `device_in` / `device_out` | Punch ผ่าน Web ไม่ใช้ SDA (W) = −0.25 — **ทั้งสองฝั่งรวมกันหักได้ไม่เกิน 0.25 คะแนนต่อวัน** |

### การลางาน

ถ้า `punch_in_adj_remark` หรือ `punch_out_adj_remark` ระบุการลา (ลางาน, ลาป่วย, ลากิจ,
ลาครึ่งวัน, ขอลา ฯลฯ) จะหัก **0.50 คะแนน** และ**ไม่หักเรื่องไม่ใช้ SDA** ของทั้งสองฝั่ง

การหัก 0.50 นี้ไปแทนยอดหักของ**ฝั่งที่ระบุการลา** ส่วนฝั่งที่ไม่ได้ระบุยังหักตามเกณฑ์เดิม

| ตัวอย่าง | ผล |
|---|---|
| หมายเหตุขา in “ช่วงเช้าลางาน” (มาสาย) + `punch_out_status = A` รถเสีย −0.50 | −0.50 (ลา) + −0.50 (รถเสีย) = 0 คะแนน |
| `punch_out_status = N` หนีงาน −1 แต่หมายเหตุขา out “ลาไปหาหมอ” | −0.50 อย่างเดียว = 0.50 คะแนน |

คำที่นับว่าเป็นการลา กำหนดไว้ที่ `LEAVE_RE` ในบล็อก `<script id="libsrc">`
โดยกรองคำว่า “เวลา” และ “ไม่แจ้งลา” ออกแล้ว

### การโยกรถข้ามโรงงาน

ดูจากข้อความที่มีคำว่า **“โยก”** ใน `punch_in_adj_remark` หรือ `punch_out_adj_remark`
แล้วแยกเป็นสองกรณี

| กรณี | ตัวอย่างข้อความ | ผล |
|---|---|---|
| **โยกมาช่วยงาน** | “ตรวจสภาพไม่ได้เนื่องจากมีการโยกย้ายรถไปวิ่งโรงงานอื่น”, “โยกมาช่วยงาน” | **ไม่หักคะแนน** เรื่องไม่ใช้ SDA แม้ `device_in` หรือ `device_out` จะเป็น `W` เพราะโยกข้ามโรงงานทำให้ Punch ด้วย M ไม่ได้ |
| **ไม่ยอมโยกตามสั่ง** | “ไม่โยกรถ”, “ไม่ปฏิบัติตามคำสั่งศูนย์ให้โยกโรงงาน”, “ไม่ยอมโยก”, “ปฏิเสธการโยกรถ” | **หัก 1 คะแนน** และหักเงินรางวัลของรถ **1,000 บาท** |

รหัส `punch_out_status = 8` (ย้ายโรงงาน) คิดแบบเดียวกัน ถ้าวันเดียวกันเกิดทั้งรหัส 8
และหมายเหตุไม่โยก **หักครั้งเดียว** ทั้งคะแนนและเงิน

เงินที่ถูกหักไปแสดงในคอลัมน์ **หักไม่โยก/ย้ายโรงงาน** ของแท็บคำนวณรางวัล
และลบออกจากรางวัลสุทธิของรถคันนั้น (ไม่ได้หักที่ จบส.) ค่าปรับอ่านจากชีต `คะแนน-Punch`
แถวที่ความหมายมีคำว่า “โยกรถ”

รูปประโยคที่ถือว่าปฏิเสธการโยก กำหนดไว้ที่ตัวแปร `MOVE_REFUSE_RE` ในบล็อก
`<script id="libsrc">` เพิ่มรูปประโยคใหม่ได้ที่นั่น ส่วนค่าหักอ่านจากชีต `คะแนน-Punch`
แถวที่ความหมายมีคำว่า “โยกรถตามสั่ง” (ถ้าไม่มีจะใช้ค่าตั้งต้น 1 คะแนน)
| `punch_out_status` | ตามชีต `คะแนน-Punch` เช่น รถเสีย = −0.5, หนีงาน/ว่าง = −1 |
| `check_time` | ไม่ตรวจรถทั้งวัน (ช่องว่าง) = −1 · ตรวจรถสาย = −0.25 |
| `device_out` | ไม่ใช้ SDA ตอน Punch out **และกลับก่อนเวลาเลิกงาน** = −0.25 (ถ้า Punch out หลังเวลาเลิกงานแล้วไม่หัก) |
| **รถเสีย** | `punch_out_name` ขึ้นต้นว่ารถเสีย — ไม่มีดีพีทั้งวัน = −1 · มีดีพีตั้งแต่ 1 เที่ยว = −0.5 |
| **ไม่ลงวิน** | `punch_out_adj_remark` มีคำว่า “ไม่ลงวิน” = −0.5 (นับรวมกับรายการหักอื่นของวันนั้น) |
| **ลางาน** | หมายเหตุมีคำว่าลางาน/ลาป่วย/ลากิจ/ขอลา ฯลฯ = −0.50 (ดูรายละเอียดด้านล่าง) |

**มาสาย กับ ตรวจรถสาย หักได้อย่างใดอย่างหนึ่งเท่านั้น**

เมื่อ `punch_in_status = O` และตรวจรถเกินเวลาเข้างาน + 30 นาที ให้ดู `punch_in_adj_remark` ด้วย

| `punch_in_adj_remark` | ผล |
|---|---|
| `device_in` / `device_out` | `punch_in_adj_remark` | ผล |
|---|---|---|
| มีฝั่งใดเป็น `W` (โรงงานแก้ไขให้) | ระบุเหตุผลไว้ เช่น เลิกดึก, ระบบขัดข้อง, ระบบคำนวณ | **ไม่หักคะแนนเลย** และไม่หักเรื่องไม่ใช้ SDA ด้วย |
| มีฝั่งใดเป็น `W` | ว่าง, “ปกติ”, จุด, ขีด หรือ “ไม่ตรวจสภาพรถเกินเวลาเข้างาน” | หัก 0.25 |
| `M` ทั้งสองฝั่ง (Punch ด้วย SDA จริง) | ระบุเหตุผลไว้ | เทียบ `check_time` กับ **ดีพีใบสุดท้ายของวันก่อน + 13 ชม.** (สิทธิ์พักของคนขับ) ยังไม่เกิน = ไม่หัก · เกิน = หัก 0.25 |
| `M` ทั้งสองฝั่ง | ว่าง, “ปกติ”, จุด, ขีด | หัก 0.25 — ถือว่าโรงงานไม่ได้แก้ไขให้ |

เส้นตายกรณีสิทธิ์พักใช้เวลาที่ช้ากว่าระหว่าง `เวลาเข้างาน + 30 นาที` กับ
`ดีพีใบสุดท้ายวันก่อน + 13 ชม.` ปรับชั่วโมงพักได้ที่ตัวแปร `REST_HOURS`

คำว่า “ปกติ” ไม่นับเป็นเหตุผลที่ยกเว้นได้ ทั้งฝั่งตรวจรถสายและฝั่ง Punch out


- `punch_in_status = T` (มาสาย) → หัก 0.25 เรื่องมาสายอย่างเดียว ไม่นำเรื่องตรวจรถสายมาหักซ้ำ
- `punch_in_status = O` (ปกติ) → เช็กว่า `check_time` ไม่เกิน
  **เวลาเข้างานโรงงาน (ชีต `เวลาทำงาน`) + 30 นาที** ถ้าเกินหัก 0.25 (เทียบระดับนาที)

กรณีไม่ตรวจรถทั้งวัน (ช่อง `check_time` ว่าง) หัก 1 คะแนนเสมอ ไม่ว่า `punch_in_status`
จะเป็น T หรือ O

### กรณี `device_out = W` (ไม่ใช้ SDA ตอน Punch out) และ `punch_out_status = O`

| `punch_out_adj_remark` | `punch_out_time` | ผล |
|---|---|---|
| “ระบบคำนวณ” | หลังเวลาเลิกงาน | ไม่หัก |
| “ระบบคำนวณ” | ก่อนเวลาเลิกงาน | หัก 1 — กลับก่อนเลิกงาน |
| ว่าง / เคาะ / จุด / ขีด / “ปกติ” | ก่อนเวลาเลิกงาน | **หัก 1** — กลับก่อนเลิกงานโดยไม่ระบุเหตุผล |
| ว่าง / เคาะ / จุด / ขีด / “ปกติ” | หลังเวลาเลิกงาน | ไม่หัก |
| ระบุเหตุผลอื่น หรือมีคำว่า “โยก” | ไม่เกี่ยว | ไม่หัก |

`punch_out_time` หลังเวลาเลิกงานแล้ว **ไม่ต้องระบุเหตุผลใด ๆ** ก็ไม่หักคะแนน

เวลาเลิกงานอ่านจากชีต `เวลาทำงาน` คอลัมน์ `OUT`

ถ้า `punch_out_status` ไม่ใช่ O (ไม่ว่า `device_out` จะเป็น M หรือ W)
ให้หักตามรหัสในชีต `คะแนน-Punch` ตามปกติ

### กรณีโรงงานขอแก้ไข — ได้เต็ม 1 คะแนน

ถ้าฝั่ง Punch in **หรือ** Punch out ฝั่งใดฝั่งหนึ่งเข้าเงื่อนไขครบทุกข้อ ถือว่าโรงงานขอแก้ไข
วันนั้นได้ 1 คะแนนเต็ม ไม่หักอะไรเลย แม้ช่อง `check_time` จะว่าง (ไม่ได้ตรวจรถ)

| เงื่อนไข | ค่าที่ต้องเป็น |
|---|---|
| `device_in` / `device_out` | `W` หรือว่าง |
| `punch_in_time` / `punch_out_time` | `00:00` |
| `punch_in_status` / `punch_out_status` | `O` |
| `punch_in_adj_remark` / `punch_out_adj_remark` | ระบุเหตุผลไว้ ต้องไม่ใช่ “ระบบคำนวณ” และไม่ใช่การเคาะ จุด ขีด หรือ “ปกติ” |

ตัวอย่างเหตุผลที่พบในข้อมูล: วันหยุดประเพณี, วันแม่, รง.หยุด, วันเฉลิมพระชนมพรรษา

### กฎที่ดูจากข้อความในช่อง `punch_out_adj_remark`

แถวในชีต `คะแนน-Punch` ที่ช่อง `In/Out` เป็น **`punch_out_adj_remark`**
จะถูกใช้เป็นคำค้น — ถ้าข้อความในช่องหมายเหตุของแถว Punch มีคำนั้นอยู่
จะคิดคะแนนรถและค่าปรับ จบส. ตามที่ระบุในแถวนั้น

| ความหมายจากระบบ | คำค้นที่ใช้ | ผล |
|---|---|---|
| ไม่ให้ความร่วมมือ | ไม่ให้ความร่วมมือ | หัก จบส. 50 บาท ในวันนั้น |
| ข้อร้องเรียน จบส.เป็นฝ่ายผิด (เพิ่ม) | ข้อร้องเรียน | ตัดทั้งโครงการ (เงินรางวัล บาท/คิว = 0) |

คำค้นคือ **คำแรก** ของช่องความหมายจากระบบ (ตัดวงเล็บออกแล้ว)
เพิ่มหรือแก้กฎได้ในไฟล์ Excel โดยไม่ต้องแก้โค้ด

### ประเภทรถ (ช่อง `รถบัญชี` ในชีต `จดทะเบียน`)

ระบบจัดกลุ่มค่าในช่องนี้ให้เหลือสองแบบ

| ค่าที่พบในไฟล์ | จัดเป็น | สิทธิ์ |
|---|---|---|
| บัญชี1, บัญชีหลัก, รถหลัก | **รถจดทะเบียน** | คิดคะแนนและรางวัลตามปกติทุกหัวข้อ |
| บัญชี2, รถสำรอง, รถเสริม | **รถเสริม** | คิดคะแนนวันทำงานและการหักเงินทุกหัวข้อเหมือนรถจดทะเบียน แต่**ไม่มีสิทธิ์ได้เงินรางวัลและการันตี** แม้จะได้ TA 1–TA 3 และไม่ถูกหักอัตราติดลบของ TA 5 / TA 6 |

ค่าเดิมในไฟล์ยังดูได้จากการวางเมาส์ที่คอลัมน์ “รถบัญชี” ในแท็บคำนวณรางวัล

**การนับคิวและรายได้** — ค่าในคอลัมน์ `dp_dispatch_qty`, `partialtcost` และ `ดีพีในวัน`
เป็นยอด **ของทั้งวัน** ถ้าวันนั้นมีหลายแถว (คนขับหลายคน หรือวิ่งข้ามโรงงาน) ค่าจะซ้ำกัน
ระบบจึงนับครั้งเดียวต่อรถต่อวัน ไม่บวกทบ

**การเฉลี่ยคิวและรายได้ของรถเสริม** — ยอดผลิต (คิว) และค่าขนส่งของรถเสริม
จะถูกย้ายไปเฉลี่ยเท่า ๆ กันให้รถจดทะเบียนที่อยู่ **โรงงานเดียวกันและผู้รับเหมาเดียวกัน**
ในเดือนนั้น ถ้ากลุ่มนั้นไม่มีรถจดทะเบียนเลย ยอดจะคงไว้ที่รถเสริมตามเดิม
ยอดรวมทั้งโครงการจึงไม่เปลี่ยน วางเมาส์ที่คอลัมน์คิวในแท็บคำนวณรางวัลเพื่อดูว่ารับเฉลี่ยมาเท่าไร

### การตัดสิทธิ์เงินรางวัล บาท/คิว

รถที่มี `punch_out_status` = **J** (ตรวจพบสารเสพติด) หรือ **K** (ตรวจพบแอลกอฮอล์ > 0 mg%)
หรือมีข้อความ **“ข้อร้องเรียน”** ใน `punch_out_adj_remark` แม้วันเดียวในเดือนนั้น
→ ไม่ได้รับเงินรางวัลแม้อยู่กลุ่ม TA 1–TA 3

แต่ถ้าคะแนนทั้งเดือนตกอยู่กลุ่ม **TA 5 (−3 บาท/คิว)** หรือ **TA 6 (−6 บาท/คิว)**
ยังต้องถูกหักตามอัตรานั้น × จำนวนคิวรวมของรถคันนั้น

ทุกกรณียังมีสิทธิ์ได้เงินการันตีตามปกติถ้าคะแนนผ่านเกณฑ์
